# nclite

**Маленький файловый сервер, совместимый с Nextcloud, для роутеров и другого слабого железа.**

[English version](README_en.md)

nclite реализует ту часть серверного API Nextcloud, которая реально нужна официальному мобильному приложению Nextcloud: просмотр, загрузка и скачивание файлов, автозагрузка фото, превью, корзина, избранное, фотоальбомы и потоковое видео. Это один статический бинарник на Go без зависимостей, кроме необязательных медиа-утилит. Он написан для домашнего роутера (Keenetic, aarch64, Entware, 512 МБ памяти) с USB-диском.

Это **не** замена Nextcloud: здесь нет приложений, календаря и контактов, публичных ссылок и версий файлов. Если вам нужны фото и файлы с телефона на вашем диске через привычное приложение и при этом небольшое потребление ресурсов (процесс сервера занимает десятки мегабайт), то это для вас.

> nclite это независимая реализация, написанная по протоколу с нуля. Проект не связан с Nextcloud GmbH и не одобрен ею. «Nextcloud» является товарным знаком его владельца и используется здесь только для описания совместимости по протоколу.

## Возможности

**Для мобильного приложения** (разрабатывалось и проверялось с Nextcloud iOS 35.2)

- Вход через браузер (Login Flow v2): приложение получает отзываемый пароль приложения.
- Просмотр, загрузка, скачивание, переименование, перемещение, копирование и удаление файлов и папок. Поддержка Range, поэтому видео перематывается.
- **Автозагрузка фото** с сохранением исходного времени изменения и загрузка больших видео по частям.
- **Превью** на сервере для JPEG, PNG, GIF, WebP, HEIC/HEIF, видео (mp4, mov, mkv и другие) и PDF: создаются один раз, кэшируются на диске и отдаются так же, как это делает оригинальный сервер.
- **Корзина** с восстановлением, окончательным удалением и автоочисткой. **Избранное.**
- **Потоковое видео** через прямые ссылки.
- **Фотоальбомы** (протокол Nextcloud Photos). Альбом хранит только список файлов, ничего не копируется.
- **Общие папки** между пользователями, только чтение или чтение и запись.
- Отображение занятого места по реальному использованию диска.

**Для вас**

- **Админка**: пользователи, статистика по папкам (файлы, папки, размер, корзина), общие папки, задачи сканирования и генерации превью с прогрессом и отменой.
- **Файловый браузер** для компьютера: дерево папок, альбомы, виды «список», «таблица», превью 512 и 1024 px, панель просмотра с изменяемой шириной, копирование, перемещение, переименование и удаление выбранных файлов. Доступен только на порту админки.
- Файлы лежат на диске **как есть** (`<data_dir>/<user>/files/...`). Добавляйте, меняйте и удаляйте их по scp или Samba, сервер подхватит изменения. Структура совпадает с каталогом данных Nextcloud, поэтому его можно [подключить на месте](#подключение-существующего-каталога-данных-nextcloud).
- Админку и файловый браузер можно спрятать от интернета, выделив им отдельный порт.

**Для слабого железа**

- Чистый Go, по умолчанию без cgo, один статический бинарник. Индекс в SQLite в режиме WAL.
- Память ограничена (мягкий лимит рантайма Go). Тяжёлая работа выполняется короткоживущими внешними процессами с низким приоритетом, по одному за раз, и память возвращается системе при их завершении.
- Превью делаются из ближайшего подходящего уже готового превью, а не декодированием оригинала заново (HEIC на 12 Мп декодируется один раз, остальные размеры получаются из результата).

## Требования

- Linux. Разрабатывался и используется на aarch64 (Keenetic с Entware); на других архитектурах должен собираться, но проверялись только aarch64 и amd64.
- Обратный прокси с HTTPS (пример для nginx есть в репозитории). Приложению iOS нужен HTTPS.
- Необязательно, для превью (ставьте нужное; превью остальных типов продолжат работать):

  | Утилита | Для чего | Типичный пакет |
  |---|---|---|
  | `ffmpeg` | картинки, видео | `ffmpeg` |
  | `heif-convert` | HEIC / HEIF | утилиты libheif (`libheif-examples`) |
  | `pdftoppm` | PDF | `poppler-utils` |

- Актуальный Go для сборки из исходников.

## Быстрый старт с opkg

```sh
# 1. Подключение feed
cat > "/opt/etc/opkg/kashtan404-keenetic.conf" <<EOF
src/gz nclite https://kashtan404.github.io/entware-repo/aarch64-k3.10
EOF

# 2. Установка зависимостей
opkg install ffmpeg poppler-utils python3 python3-pip nginx-ssl nginx-mod-headers-more
pip3 install heif-convert

# 3. Установка nclite
opkg update
opkg install nclite

# 4. Настройка конфига /opt/etc/nclite/config.json
Обязательно указать корректные db_path, data_dir, cache_dir, listen, base_url, admin_listen, admin_url
Дополнительно можно указать исключения для расширений для которых не нужно превью через exclude_ext

# 5. Настройка конфигов nginx
шаблоны можно взять в https://github.com/kashtan404/nclite/tree/master/deploy
nginx.conf и conf.d/nclite.conf

# 6. Создайте первого пользователя. Командная строка создаёт администраторов,
#    обычных пользователей добавляйте потом в админке.
nclite -config /opt/etc/nclite/config.json user add alice

# 7. Запуск
/opt/etc/init.d/S99nclite start
/opt/etc/init.d/S80nginx start
```

## Ручная установка

```sh
# 1. Сборка (на любой машине с Go)
go mod tidy
make build-arm64            # dist/nclite, статический, без cgo. Для других платформ:
                            # GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -o dist/nclite ./cmd/nclite

# либо скачать и распаковать необходимый релиз
https://github.com/kashtan404/nclite/releases

# 2. Установка на устройство (пути как в Entware по умолчанию)
scp dist/nclite router:/opt/bin/
ssh router
mkdir -p /opt/etc/nclite
# скопируйте deploy/config.example.json в /opt/etc/nclite/config.json и поправьте:
# как минимум data_dir, cache_dir и base_url

# 3. Создайте первого пользователя. Командная строка создаёт администраторов,
#    обычных пользователей добавляйте потом в админке.
nclite user add alice

# 4. Запуск
nclite serve                # или установите deploy/S99nclite как init-скрипт

# 5. Плюс аналогично с nginx из быстрого старта
```

Дальше поставьте перед ним nginx (или другой прокси) с HTTPS, см. [Развёртывание](#развёртывание), и введите адрес сервера в приложении Nextcloud. Приложение откроет страницу входа nclite, после входа вы подключены.

## Настройка

Один JSON-файл, по умолчанию `/opt/etc/nclite/config.json` (ключ `-config` меняет путь). Если файла нет, берутся значения по умолчанию. Пример: [`deploy/config.example.json`](deploy/config.example.json).

| Ключ | По умолчанию | Значение |
|---|---|---|
| `listen` | `127.0.0.1:8085` | Адрес основного слушателя (того, что стоит за обратным прокси). |
| `base_url` | пусто | Публичный адрес, например `https://cloud.example.com`. Используется в ответах входа. Если пусто, берётся из заголовков запроса. |
| `trust_proxy` | `true` | Доверять `X-Forwarded-*` и `X-Real-IP`. Безопасно только если до слушателя доходит один ваш прокси. |
| `data_dir` | `/opt/var/nclite/data` | Файлы пользователей: `<data_dir>/<user>/files`. Может быть на другом диске, чем база. |
| `db_path` | `/opt/var/nclite/nclite.db` | База SQLite (идентификаторы, etag, пользователи, шары, альбомы). |
| `cache_dir` | `/opt/var/nclite/cache` | Кэш превью. Можно удалить в любой момент. |
| `product_name` | `Home Cloud` | Название в приложении и на веб-страницах. |
| `trash_days` | `30` | Удалять из корзины через N дней. `0` хранить вечно, `-1` корзина выключена (удаление сразу). |
| `rescan_minutes` | `360` | Как часто пересматривать папки всех пользователей на предмет изменений вне nclite. `0` отключает периодическую проверку (аккаунты, которые ни разу не сканировались, всё равно сканируются один раз после запуска). |
| `mem_limit_mb` | `160` | Мягкий лимит памяти рантайма Go. |
| `gc_percent` | `50` | Порог сборщика мусора Go. Меньше значит меньше памяти и больше нагрузки на процессор. |
| `access_log` | `false` | Писать в лог каждый запрос (удобно, чтобы увидеть, что просит клиент). |
| `admin_listen` | пусто | Адрес **отдельного слушателя для админки и файлового браузера**, например `127.0.0.1:8090`. Если задан, ни то ни другое на основном порту не обслуживается. |
| `admin_url` | пусто | Адрес, по которому вы открываете админку, например `http://192.168.1.1:83/admin`. Путь задаёт префикс админки (по умолчанию `/admin`), схема определяет флаг `Secure` у cookie. |
| `web_path` | `/cloud` | Путь файлового браузера на порту админки. Требует `admin_listen`. |
| `preview.enabled` | `true` | Включить или выключить превью. |
| `preview.workers` | `1` | Сколько превью рендерится параллельно. На слабом роутере оставьте 1. |
| `preview.pregen` | `[512]` | Квадратные размеры, которые рендерятся в фоне после загрузки. |
| `preview.ffmpeg` | `ffmpeg` | Путь или имя утилиты. |
| `preview.heif_convert` | `heif-convert` | Поддерживаются и старая (`in out.jpg`), и новая (`in -o out -f jpg`) командная строка. |
| `preview.pdftoppm` | `pdftoppm` | Путь или имя утилиты. |
| `preview.nice` | `10` | Уровень `nice` для утилит; `0` отключает. |
| `preview.timeout_sec` | `90` | Прервать рендер, который идёт дольше. |
| `preview.quality` | `5` | Качество JPEG у ffmpeg, от `2` (лучшее) до `31`. |
| `preview.exclude_ext` | `[]` | Расширения, для которых превью не делаются, например `["pdf", ".avi"]`. Приложение покажет обычную иконку. |

## Развёртывание

### Обратный прокси и HTTPS

В [`deploy/nginx.conf`](deploy/nginx.conf) есть готовый блок `server`. Важные для файлового сервера настройки:

```nginx
client_max_body_size 0;
proxy_request_buffering off;   # загрузки идут потоком, ничего не складывается во временные файлы
proxy_buffering off;
proxy_http_version 1.1;
```

### Как спрятать админку от интернета

Задайте `admin_listen`, и админка с файловым браузером получат отдельный слушатель:

```json
"admin_listen": "127.0.0.1:8090",
"admin_url":    "http://192.168.1.1:83/admin"
```

Тогда основной порт отвечает 404 на `/admin` и `/cloud`, а порт админки больше ничего не обслуживает. В примере nginx есть второй блок `server`, который слушает только LAN-адрес роутера и проксирует на него. Не привязывайте `admin_listen` к `0.0.0.0` и не пробрасывайте этот порт из интернета. Если адрес при загрузке ещё не поднят, nclite не завершается, а повторяет попытку и пишет ошибку в лог.

### Запуск как сервис

[`deploy/S99nclite`](deploy/S99nclite) это init-скрипт для Entware (`start-stop-daemon`). Скопируйте его в `/opt/etc/init.d/`. Лог пишется в `/opt/var/log/nclite.log`.

## Как пользоваться

**Подключение телефона.** Введите адрес сервера в приложении Nextcloud. Оно откроет страницу входа nclite, после входа приложение сохранит пароль приложения. Кнопка «Sign out devices» в админке отзывает их.

**Админка** (`/admin` на порту админки): создание пользователей и смена паролей, папка каждого пользователя, число файлов, размер и корзина, выход всех устройств, удаление аккаунта (см. ниже), общие папки и задачи:

- *Scan files* обходит папки и обновляет индекс. Это делает цифры точными и подхватывает файлы, добавленные вне nclite.
- *Generate previews* заранее готовит миниатюры для всех пользователей, одного или одной папки, с прогрессом, оценкой оставшегося времени и отменой. Размеры обрабатываются от большего к меньшему, чтобы меньшие обходились дёшево. В форме заранее подставлены размеры, которые приложения реально запрашивают.

**Удаление аккаунта никогда не удаляет файлы.** Папка остаётся на диске и появляется в списке «Folders without an account»; если создать аккаунт с тем же именем, она подключится снова.

**Общие папки.** Администратор делится папкой одного пользователя с другим, только чтение или чтение и запись. У получателя она появляется в корне как `Папка (владелец)` и сохраняет идентификаторы файлов, поэтому превью и избранное остаются.

**Файловый браузер** (`/cloud/` на порту админки): войдите под своим именем и паролем и увидите то же, что в приложении. Слева дерево папок, под ним альбомы; сверху действия над отмеченными файлами: копировать, переместить, переименовать, удалить, новая папка; виды «список», «таблица», маленькие (512 px) и большие (1024 px) превью; панель просмотра, которую можно включать и растягивать, показывает фото (включая HEIC), видео, аудио, PDF и текст.

**Альбомы.** Создаются во вкладке «Фото» / «Альбомы» приложения. Альбом хранит файлы по идентификатору, поэтому переименование или перемещение фото его не ломает, а удаление альбома никогда не трогает сами фото.

**Корзина.** Удаление из приложения переносит объект в папку корзины рядом с вашими файлами (мгновенное переименование). Восстановить, удалить окончательно или очистить корзину можно из приложения.

**Командная строка**

```
nclite [-config file.json] serve
nclite [-config file.json] user add <name> [password]     # создаёт администратора
nclite [-config file.json] user passwd <name> [password]
nclite [-config file.json] user list
```

Пароль можно также передать через `NCLITE_PASSWORD` или stdin.

## Подключение существующего каталога данных Nextcloud

Структура та же (`<data>/<user>/files/`), поэтому `data_dir` можно направить на каталог данных Nextcloud, ничего не копируя. nclite игнорирует всё, что не знает (`appdata_*`, логи, `cache`, `files_trashbin`, `files_versions` и т. д.), и создаёт свои папки `tmp` и `trash` внутри папки пользователя.

1. Сначала сделайте резервную копию и остановите Nextcloud. Не запускайте оба сервера на одном каталоге с записью.
2. Откройте админку. В разделе «Folders without an account» перечислены найденные папки.
3. Создайте аккаунт с тем же именем и новым паролем (пароли Nextcloud импортировать нельзя). Индексация существующих файлов запустится сама, ход виден в админке.

Переносятся ваши файлы. Не переносятся: идентификаторы файлов, избранное, шаринг, комментарии, версии, старая корзина, превью Nextcloud. На каждом устройстве придётся войти заново.

## Как это устроено

```
<data_dir>/<user>/files/   ваши файлы, как есть
<data_dir>/<user>/trash/   объекты из корзины (та же файловая система: перенос это переименование)
<data_dir>/<user>/tmp/     загрузки в процессе
<cache_dir>/<fileid>/...   кэш превью
<db_path>                  индекс SQLite: идентификаторы, etag, пользователи, пароли приложений, шары, альбомы, избранное
```

- **Индекс.** Сами файлы в базе не хранятся. SQLite только выдаёт стабильные идентификаторы и etag и синхронизируется лениво: папка сверяется с диском при каждом листинге, плюс периодическое сканирование. Etag папки меняется при любом изменении внутри и поднимается до корня, по этому клиенты понимают, что обновлять.
- **Согласованность.** Переименование, корзина, восстановление, завершение загрузки и создание папки упорядочены относительно листингов каталогов, а листинг перед записью перепроверяет диск, поэтому медленный листинг не может занести в индекс устаревший снимок. Пути всегда канонические; на дисках без учёта регистра (FAT, exFAT) запросы приводятся к написанию, которое лежит на диске. Если диск пользователя не смонтирован, nclite отвечает 503, а не создаёт заново пустые папки и не «забывает» всё.
- **Превью.** Делаются утилитами `ffmpeg` / `heif-convert` / `pdftoppm` как дочерними процессами под `nice`, для JPEG используется shrink-on-load и учитывается ориентация EXIF. Результаты кэшируются по идентификатору и версии файла. Меньшее превью получается из уже готового большего, когда это безопасно, иначе делается из оригинала.

**Покрытие протокола**

| Область | Адреса |
|---|---|
| Статус, вход | `status.php`, `ocs/v{1,2}.php/cloud/capabilities`, `cloud/user`, `cloud/users/<id>`, Login Flow v2, отзыв пароля приложения |
| Файлы | WebDAV `/remote.php/dav/files/<user>`: PROPFIND, GET (Range), PUT (`X-OC-Mtime`), MKCOL, DELETE, MOVE, COPY, PROPPATCH (избранное), REPORT (список избранного) |
| Загрузка | Загрузка по частям v2 `/remote.php/dav/uploads/<user>` |
| Корзина | `/remote.php/dav/trashbin/<user>`: список, восстановление, удаление, очистка, превью |
| Превью | `index.php/core/preview` (по id или пути), `preview.png` |
| Видео | `ocs/v2.php/apps/dav/api/v1/direct` и `/remote.php/direct/<token>` |
| Альбомы | `/remote.php/dav/photos/<user>/albums`, `COPY` в альбом, `SEARCH` по идентификатору файла |

Всё остальное под `ocs/` получает пустой, но корректный ответ OCS, чтобы клиенты не ломались на функциях, которых в nclite нет.

## Безопасность

- Пароли хешируются PBKDF2-HMAC-SHA256 (только для интерактивного входа). Устройства используют случайные 256-битные пароли приложений, которые хранятся как SHA-256, поэтому проверка запроса дешёвая. Неудачные входы ограничиваются по IP.
- Сессии админки и файлового браузера это подписанные cookie, ограниченные своим путём, а любой изменяющий запрос требует токен CSRF. Админка не выполняет скриптов вообще; файловый браузер разрешает скрипты и стили только со своего адреса и выводит имена файлов как текст.
- Файловый браузер показывает в окне только фото, видео, аудио, PDF и простой текст. HTML, SVG и всё остальное отдаётся только как скачивание, поэтому файл из общей папки не может выполниться как страница сайта.
- Ни один путь в коде не удаляет папку пользователя. Удаление корня аккаунта или корня общей папки запрещено.
- Завершайте TLS на прокси, держите `listen` на loopback-адресе, `admin_listen` в локальной сети, а `trust_proxy` оставляйте включённым, только если до `listen` доходит один ваш прокси.

## Ограничения

- Только перечисленные выше функции. Нет публичных ссылок и API шаринга (поэтому экран «Подробности» в приложении скрыт), ленты активности, уведомлений, комментариев, версий файлов, сквозного шифрования, поиска, квот на пользователя и общих альбомов.
- Общие папки создаёт администратор, а не пользователи.
- Проверялось с приложением Nextcloud для iOS. Клиенты для Android и компьютера не проверялись.
- Количество файлов и размеры точны после полного сканирования, до него они учитывают только то, что nclite уже видел.
- На дисках без учёта регистра два имени, отличающиеся только регистром, не могут существовать рядом, как в Windows.
- Перемещение или копирование файла между аккаунтами (в общую папку или из неё) реально копирует данные, и у нового файла новый идентификатор.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Превью нет совсем | Утилиты должны быть в `PATH` сервиса (или укажите полный путь в конфиге). Выполните ту же команду вручную. Включите `"access_log": true` и прочитайте лог. |
| Нет превью HEIC | `heif-convert` нужен декодер HEVC (например, плагин libde265). |
| HTTP 503 «storage unavailable» | Диск с данными не смонтирован. nclite не трогает пустую точку монтирования; смонтируйте диск и повторите. |
| Загрузка падает за nginx | Укажите `client_max_body_size 0;` и `proxy_request_buffering off;`. |
| Приложение не принимает сервер | Нужен HTTPS и сертификат, которому доверяет телефон. |
| SQLite не запускается на старом ядре | Соберите на самом устройстве через `make build-cgo` (использует `mattn/go-sqlite3`, нужен gcc). |
| После ручного добавления файлов цифры занижены | Запустите «Scan files» в админке. |

## Разработка

```sh
make test           # go test -race (под тегом cgo используется драйвер SQLite с cgo)
make build-arm64    # статический бинарник linux/arm64, чистый Go
make build-cgo      # нативная сборка с cgo-драйвером SQLite
```

Структура:

```
cmd/nclite        точка входа и командная строка
internal/config   файл конфигурации
internal/store    SQLite: пользователи, индекс, шары, альбомы, корзина, избранное
internal/vfs      разбор путей, шары, сверка каталогов, учёт регистра
internal/preview  рендер и кэш превью
internal/server   HTTP: API Nextcloud, WebDAV, админка, файловый браузер (static/, templates/)
deploy/           пример конфига, конфиг nginx, init-скрипт
```

Драйвер по умолчанию `modernc.org/sqlite` (чистый Go). Тесты запускаются с тегом `cgo_sqlite`, который подменяет его на `mattn/go-sqlite3`.
